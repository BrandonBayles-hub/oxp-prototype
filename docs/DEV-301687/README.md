# DEV-301687 — Super Agent 1.0 Epic Content

This folder is the source of truth for the Jira epic **DEV-301687: Super Agent 1.0** ([live link](https://entrata.atlassian.net/browse/DEV-301687)). Content was authored using the `write-jira-epic` Cursor skill against the Super Agent 1.0 functionality already implemented in this prototype, then pushed to Jira via the REST API directly (the Entrata Jira MCP server was offline).

## Live state on Jira

- **All 9 FE Doc text fields** (Before, After, NOT Included, New Permissions, Settings, Who, Why, FAQs, Adoption Method Details) — populated.
- **All 7 metadata selects / multi-selects** (Feature Essential Status, Phased Rapid Release, Adoption Method, Customer Facing / Release Note, Feature Flag Type, Impact Areas, Critical Workflows Impacted) — populated with the exact option IDs from the skill's field reference.
- **Description** — sections 1–6 of the engineering spec (Problem Definition, Solution — Workflows, Error & Failure States, Loading & Empty States, API Contracts, Business Logic, User Stories) plus an info panel pointing at the continuation comment.
- **Continuation comment** — sections 7–12 of the engineering spec (SDET, Amplitude, Success Metrics, Feature Flag & Rollback, Vertical Matrix, Accessibility) plus Appendix A.

The description was split at the § 6 / § 7 boundary because the Jira description field has an ~85 KB ADF content limit and the full spec is ~123 KB.

| File | Purpose |
|---|---|

| `description.md` | Full engineering spec — all 13 sections (Problem, Workflows, Errors, Loading & Empty States, API Contracts, Business Logic, User Stories, SDET Test Cases, Amplitude Events, Success Metrics, Feature Flag/Rollback, Vertical Impact, Accessibility, Appendix). Technical voice. |

| `md-to-adf.mjs` | Markdown → ADF (Atlassian Document Format) converter built on `marked`'s lexer. Handles headings, paragraphs, bold/italic, inline code, code blocks, bullet/ordered lists, links, block quotes, horizontal rules, GitHub-style tables. Strips invalid mark combinations (e.g. `code`+`strong` which ADF rejects). |
| `push-final.mjs` | The push script that does the actual work: PUT `description` (sections 1–6 with footer panel), DELETE any prior continuation comments, POST the continuation comment (§ 7 – Appendix A), verify by re-fetching. Reads credentials from `$JIRA_ENV_FILE` (`~/.config/jira-cli/.env`). Idempotent — safe to re-run. |
| `build-payload.mjs` | Builds `jira-payload.json` (the JSON inventory of what each field should contain). Optional — `push-final.mjs` is the live push path. |
| `jira-payload.json` | Static JSON inventory of FE Doc + metadata payloads keyed by `customfield_*` IDs (markdown form). Used for documentation/inspection. |
| `jira-payload.adf.json` | Last full ADF payload generated by `push-to-jira.mjs --dry-run` — useful when debugging field-level ADF issues against Atlassian's spec. |
| `push-to-jira.mjs` | Single-shot push (description + FE Doc + metadata in one PUT). Kept as a reference; the live push uses `push-final.mjs` because the description must be split into description + continuation comment. |
| `push-debug.mjs` | Field-subset / single-field debug pusher used to isolate the 400 INVALID_INPUT error. Useful if a future schema change re-introduces a field validation failure. |
| `push-description-bisect.mjs` | Block-range debug pusher used to bisect the description size limit. Useful if the content limit changes or if a future addition breaks ingest at a specific block. |

## Re-pushing after edits

If you edit `fe-doc.md` or `description.md`:

```bash
# Push everything (FE Doc fields, metadata, description, continuation comment)
node docs/DEV-301687/push-final.mjs

# If you also want to refresh the FE Doc + metadata fields (push-final.mjs only touches description + comment):
node docs/DEV-301687/push-debug.mjs textareas
node docs/DEV-301687/push-debug.mjs selects
node docs/DEV-301687/push-debug.mjs multis
```

Credentials come from `$JIRA_ENV_FILE` (defaults to `~/.config/jira-cli/.env`). The push scripts use Basic auth (`email:api_token`) against `https://entrata.atlassian.net/rest/api/3/`.
